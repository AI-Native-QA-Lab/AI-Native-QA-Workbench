# Contributing

## Development Model

This project uses Contract-first development and TDD.

For core behavior:

1.  Define or read the contract.
2.  Describe expected behavior and acceptance criteria.
3.  Write the failing test.
4.  Confirm RED.
5.  Implement the minimum behavior.
6.  Confirm GREEN.
7.  Refactor.
8.  Run architecture and regression checks.
9.  Update documentation.

## Pull Requests

PRs should be small enough to review and should identify:

-   behavior changed
-   contract/domain impact
-   tests added
-   architecture impact
-   i18n impact
-   documentation impact

See `AGENTS.md` for mandatory repository rules.
